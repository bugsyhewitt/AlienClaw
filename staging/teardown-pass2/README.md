## Procedure (in this order)

**Recommendation: close #653 and land pass 2 as ONE code PR**, with `ci-pass2.patch` landed
on `main` first as its own small PR by someone holding a workflow-scoped token. That is the
architecture review's Q4 recommendation: one atomic teardown avoids a window where half the
agent product is gone, and avoids the `seed/martians/.gitkeep` ordering edge. The kit works
either way: if #653 merges before step 2, step 2 still applies (the table above) and
deletes the rest, including the `.gitkeep` that #653 adds. Merging #653 first is safe but
buys nothing.

**Step 1. Bugsy, with a workflow-scoped token: land `ci-pass2.patch` on `main` by itself, first.**

```bash
git switch -c chore/ci-pass2 origin/main
git apply --check staging/teardown-pass2/ci-pass2.patch && git apply staging/teardown-pass2/ci-pass2.patch
git commit -am "ci: trim agent-product steps, ratchet coverage floors, add KEEP TS coverage gate"
git push -u origin chore/ci-pass2      # workflow-scoped token
gh pr create --base main --fill        # wait for the 3 required checks, then merge
```

The patched workflow is safe to land on today's `main`, before any code is deleted:

- Every removed step and the removed `install-smoke` job are non-required. The three
  required job names are unchanged.
- The **raised Python floors (98/98/98) hold on unmodified `main`**: measured there,
  genome is 99.65%, evolution 99.66%, diagnostics 98.74% (same commands, `401f4099`).
- The **new KEEP TypeScript step passes on unmodified `main`**: its 12 named test files
  (`test/net/` does not exist there yet) and the 7 source files it measures are byte-identical on `main`, on #653's branch, and on the
  trimmed tree (checked with `git diff --quiet origin/main <ref> -- <those paths>
  vitest.config.ts`), so it measures the same 96.06% lines / 86.68% branches on all three.
- Between step 1 and step 2, `vitest`'s default include still runs the not-yet-deleted
  tests, so the intermediate state stays green.

Landing CI first means the code PR in step 2 never touches `.github/workflows/`. That lets
an agent whose token lacks `workflow` scope push and update the code PR. If the two were
combined in one PR, an agent could never push to that branch again after a rebase.

**Step 2. Anyone (no workflow scope needed): the code PR. Then close #653.**

```bash
git switch -c chore/teardown-pass2 origin/main     # works with or without #653 merged
xargs git rm -q --ignore-unmatch -- < staging/teardown-pass2/delete-list.txt
git apply --check staging/teardown-pass2/decoupling.patch && git apply --index staging/teardown-pass2/decoupling.patch
git commit -m "chore: teardown pass 2 — remove agent product (governance/agents/brains/martians/bridge/cli/...)"
```

`delete-list.txt` has no paths with spaces, so plain `xargs` is safe. `git apply --index`
stages the two new files too. Push, open the PR, and merge once the 3 required checks are
green. If #653 is still open, close it: step 2 deletes a superset of what #653 deletes,
including the two `it.skip`-ed governance tests.

- **Test files are named explicitly**, not whole directories. `test/registry/` and
  `test/telemetry/` still hold DROP tests on `main`; naming files makes the gate measure the
  same thing before and after step 2, which is what makes step 1 safe. The one directory is
  `test/net/`, which holds only hardened-fetch tests, so new ones are gated without another
  workflow edit. vitest ignores a filter that matches nothing (checked on `main`).
- **The streaming-cap probe is left out.** It is an RSS bound (R-013), which v8
  instrumentation would distort; it already runs in the Unit tests job.
- **Not covered:** `src/alienclaw/evolution/**/*.ts` (graph + reflective, 27 files) and
  `src/alienclaw/api/**` (has its own gate). See D-4.

## Risks the dry run cannot see

1. **MySQL-backed tests did not run.** I didn't start a database, and
   `ALIENCLAW_TEST_DB_URL` was unset, so the DB-backed `test/api/` suites (`ts-storage`, the
   handler integration suites, and others) self-skipped in both vitest runs. Neither
   "Run migrations" step ran, and the API coverage thresholds (lines 75 / branches 63) could
   not be checked: DB-less coverage is far lower and would fail them spuriously. The kit
   does not touch `src/alienclaw/api/`, `test/api/`, or `migrations/`. The api code imports
   only kept modules (`utils.ts`, `registry/genome-codec.ts`, `telemetry/telemetry-reader.ts`).
   Expect these steps to behave exactly as on `main`. The KEEP TypeScript gate needs no DB.
2. **actionlint and the no-tabs check did not run.** actionlint isn't installed here. The
   patched `ci.yml` has 0 tab characters; the dry run's guard parsed the new step's `run:`
   block out of it and executed it verbatim.
3. **shellcheck did not run** (not installed). The code PR only deletes shell scripts. If
   `staging/teardown-pass2/` itself is ever committed, the Shell job will lint `dry_run.sh`,
   which I could only check with `bash -n`.
4. **Toolchain drift.** Local runs used Python 3.14.9 (CI uses 3.12), ruff 0.15.20 (CI
   installs the latest `<1.0`), Node v24 (CI uses 22), and the main checkout's existing
   `node_modules` (CI uses `pnpm install --frozen-lockfile`). The new floors and thresholds
   leave room for this; watch the first real CI run.
5. **Suites outside CI.** `pytest` over `test/tools/` (except `test_web_search_backend.py`)
   and `test/fitness/` is not in CI, and the kit does not add it. The dry run runs
   `test/fitness/` plus the pkt087 test as a kit-only check so the kept conformance module
   is proven green. Three tuner modules (`{mangle,ouija,pho3nix}_tuner.{run_ga,fitness_adapter}`)
   import cleanly on the trimmed tree.
6. **No local `__pycache__` problem in CI.** On a long-lived checkout, `git rm` leaves
   untracked `__pycache__/` directories behind under the deleted Python packages. They are
   gitignored, so CI never sees them.

## Regenerating the kit

1. To change what goes, change the manifest (`staging/tools/build_drop_manifest.py`, built
   at `origin/main`) or, for a kit-only exception, `KIT_DECISIONS` / `KIT_KEEPS` in
   `gen_delete_list.py`. Then run `python3 gen_delete_list.py > delete-list.txt` and read
   its stderr summary. Defaults: repo `/home/xil/dev/alienclaw`, base `origin/main`,
   manifest `../../docs/salvage/drop-manifest.json`. `--base origin/chore/teardown-pass1`
   gives the same list.
2. Create a throwaway worktree and link `node_modules` into it:
   `git -C /home/xil/dev/alienclaw worktree add --detach .claude/worktrees/pass2-dryrunN origin/main`,
   then `ln -s /home/xil/dev/alienclaw/node_modules .claude/worktrees/pass2-dryrunN/node_modules`.
3. In that worktree:
   - Apply the current kit: delete the listed paths, then `git apply decoupling.patch ci-pass2.patch`.
   - Make your edits.
   - Regenerate the patches:
     - `git diff --no-color --no-ext-diff -- .github/workflows/ci.yml > ci-pass2.patch`
     - modifications, then each new file appended:
       ```bash
       { git diff --no-color --no-ext-diff --diff-filter=M -- . ':(exclude).github/workflows/ci.yml'
         for f in src/alienclaw/diagnostics/audit_types.py test/fitness/fixtures/output_contracts.json; do
           git diff --no-color --no-ext-diff --no-index -- /dev/null "$f"
         done; } > decoupling.patch
       ```

     The decoupling patch carries modifications and the two new files; deletions live in
     `delete-list.txt`.
4. Restore the worktree to pristine: `git -C <wt> checkout -- . && git -C <wt> clean -fdq`.
5. Run `bash dry_run.sh <wt>`. It refuses a dirty worktree. By default it gates through
   the session `heavy.sh` (`HEAVY=...`). Set `HEAVY=/usr/bin/env` when you are already
   inside a `heavy.sh` call, because nested flocks deadlock, or when the scratchpad copy of
   `heavy.sh` is gone. It wipes `last-run/`, so copy the `00-*` evidence logs out first and
   put them back afterwards.
6. Remove the worktree: `git -C /home/xil/dev/alienclaw worktree remove --force .claude/worktrees/pass2-dryrunN`.
