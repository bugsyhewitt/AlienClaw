# Contributing

Thanks for helping. This library makes security decisions in two languages that must agree,
so the workflow is built around one rule: **every behaviour change starts as a vector.**

Found a way around a guard? Do not open a public issue or pull request. Follow
[SECURITY.md](SECURITY.md) instead.

## Layout

| Path | What it is |
|---|---|
| `policy/blocklist.v1.json` | The block list, the single source of every range and name both guards refuse |
| `policy/gen_python.py`, `policy/gen-ts.mjs` | Generate each language's table from it (committed, marked GENERATED) |
| `vectors/*.json` | The shared corpora: SSRF (`ssrf-vectors.json`), redirects (`redirect-vectors.json`), filesystem (`fs-vectors.json`), with each language's recorded verdict |
| `vectors/DIFFERENCES.md`, `vectors/REDIRECT-DIFFERENCES.md` | Every vector on which the languages differ, grouped, with the strictest-wins reading |
| `docs/parity.md` | Generated by `tools/render_parity.py` from the policy and the differences |
| `python/` | The Python package, its tests and `conftest.py` (fake resolver) |
| `ts/` | The TypeScript package and its tests |
| `tools/` | `wall_check.py`, `render_parity.py`, `offline.sh` |

## The corpus-first workflow

1. **Write the vector first.** Add the input that shows the behaviour you want to change to
   the right corpus: a URL or IP to `vectors/ssrf-vectors.json`, a redirect chain to
   `vectors/redirect-vectors.json`, a path and layout to `vectors/fs-vectors.json`. Use a
   new `id` (never reuse one), a `rationale` and `refs` (an RFC section, an IANA registry,
   or `control` for a public control). For a host-name vector give `resolves_to`, or it
   tests NXDOMAIN instead of the policy you meant. For a parser-differential vector give a
   public answer, so a `block` must come from the parser rule and not from DNS. The schema
   and harness rules are in `vectors/README.md`.
2. **Record what the code does today**, before changing it:

   ```bash
   python3 vectors/generate.py --write      # SSRF corpus: runs both languages
   ```

   The redirect and filesystem corpora are recorded by their own harnesses; see the
   docstrings of `python/tests/test_shared_redirect_vectors.py`,
   `python/tests/test_shared_fs_vectors.py` and their TS twins.
3. **Change the code in both languages**, or the policy table (below), until the recorded
   verdict is the one you want. A change to only one language is welcome when it brings
   that language into line with the other, and then it says so.
4. **Re-record, and read the diff.** Every changed `expected` value is a behaviour change.
   Your pull request must explain each one. If the languages now differ on a vector, or
   stop differing, update `vectors/DIFFERENCES.md` (every `python != ts` vector appears
   there exactly once).
5. **Regenerate the derived files** and run everything (below).

A change with no vector is fine only when no verdict can move: documentation, refactoring
that the existing corpus already covers, tooling.

## Changing the block list

Edit `policy/blocklist.v1.json` only; never edit a generated file. Then:

```bash
python3 policy/gen_python.py && node policy/gen-ts.mjs   # rewrite both tables
python3 vectors/generate.py --write                      # re-record the SSRF verdicts
python3 tools/render_parity.py                           # rewrite docs/parity.md
```

Each generated file carries the SHA-256 of the JSON, so any edit (a rationale too) fails the
drift tests until both generators have run. The schema, the profiles (`per-language`,
`strictest-wins`) and the matching rules are in `policy/README.md`.

## Checks to run before you push

All of these run offline. CI runs the same ones; `tools/offline.sh` gives a loopback-only
network namespace on Linux, so a test that quietly needs the internet fails.

```bash
# drift
python3 policy/gen_python.py --check && node policy/gen-ts.mjs --check
python3 tools/render_parity.py --check
python3 tools/wall_check.py --tests

# Python (from python/)
ruff check . && mypy --strict --python-version 3.11 src/<<PY_IMPORT_NAME>>
bash ../tools/offline.sh python -m pytest -q

# TypeScript (from ts/)
npm ci
./node_modules/.bin/tsc -p tsconfig.json --strict && ./node_modules/.bin/biome ci .
bash ../tools/offline.sh ./node_modules/.bin/vitest run
```

## Rules for code and tests

- **No runtime dependencies**, in either package. Development dependencies are pinned
  (`python/requirements-dev.txt` with hashes, `ts/package-lock.json`).
- **No test may touch the network.** Python tests use the fake resolver in `conftest.py`,
  which also refuses every connect; TS tests mock `node:dns` and stub `transport.request`
  (not `globalThis.fetch`, which the pinned transport never calls). A test that needs a
  real server listens on `127.0.0.1` and allows loopback for itself only.
- **Fail closed.** When a guard cannot decide (unparseable input, an unknown address family,
  an uninspectable path), it refuses.
- **Messages are read by the model.** A refusal message must not name an address learned
  from DNS, and URLs in messages are redacted (userinfo, query, fragment). Details for logs
  go on the exception's attributes.
- **A known gap is a test.** If you find a limit you cannot fix, add it to the README's "Not
  covered" section and pin it with a test that flips when someone fixes it.
- Python: ruff (line length 100), mypy `--strict`, Python 3.11 and later. TypeScript:
  `tsc --strict`, biome, Node 22 and later.
- No names, paths or ticket numbers from other projects (`tools/wall_check.py` enforces
  this in CI).

## Versioning and the changelog

MAJOR.MINOR moves in lockstep across both languages and equals the policy and corpus
version; PATCH is per language.

| Change | Version bump | CHANGELOG section |
|---|---|---|
| A vector that documents existing behaviour; rationale or refs reworded | patch | none needed |
| One language brought into line with the corpus | patch, that language | Python or TypeScript |
| A recorded verdict changes (stricter default) | minor | Policy |
| A default becomes looser | minor, plus a security note | Policy |
| The vector file format changes | `schema_version` bump | Policy |

Add your entry under `## [Unreleased]` in [CHANGELOG.md](CHANGELOG.md).
